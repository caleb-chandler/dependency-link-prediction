**Real cause, found via a standalone microbenchmark** (isolated from the full pipeline, ran in seconds
instead of another 12-minute cycle): `sm.add_constant()` on a DataFrame inserts the new `'const'`
column as a *separate internal memory block* from the original data (confirmed:
`len(df._mgr.blocks) == 2` even after force-casting the whole frame to float64). A DataFrame split
across 2 blocks has no single contiguous buffer, so converting it to one 2D array for the model
*always* copies — dtype-matching only avoids a copy when there's already one block to reuse. Passing a
**raw numpy ndarray** instead of a DataFrame confirmed zero-copy (`np.shares_memory(model.exog, arr) ==
True`, no RSS change at all in the microbenchmark) since `Logit.__init__`'s `np.asarray(arr, dtype=float)`
on an array that's already a single float64 buffer is a true no-op.

**Fix:** consolidate to a plain ndarray ourselves via `X_train.to_numpy(dtype=np.float64)` right before
`sm.Logit(...)`, instead of passing the (2-block) DataFrame. Column names are lost on a raw-array model
by default (`exog_names` become generic `x1, x2, ...`), so restored them via `model.data.xnames =
['const'] + feature_names` right after construction (this is the same attribute the public
`exog_names` property reads from) — needed so the "Regression Table" cell's `coef_df.index.str.
startswith('emb_')` filtering keeps working. Applied to both the link and strength fits. Pure

**Read statsmodels' actual source** (`discrete_model.py`) rather than keep guessing from the outside.
`Logit.score()` (the gradient, used during L-BFGS iterations) is implemented efficiently — a proper
BLAS matrix-vector product, no large temporaries. But `Logit.hessian()` — called **once, after fitting
converges**, by `statsmodels.base.model.LikelihoodModel.fit()` (`elif not skip_hessian: H = -1 *
self.hessian(xopt)`, in `base/model.py`, run for *every* solver, not just Newton, since it's needed for
the covariance matrix / standard errors / p-values / CIs) — does `-np.dot(L*(1-L)*X.T, X)`. `X.T` is
shape (p, n); multiplying it by the length-n vector `L*(1-L)` forces a full new (p, n) array into
existence before the final matmul. At our scale that's another ~8 GiB, one-shot, right when `.fit()`
was dying. `skip_hessian=True` would avoid it but also skips computing bse/p-values/CIs entirely, which
the Regression Table cells need — not usable.

**Fix: `_chunked_logit_hessian()`**, monkeypatched onto `sm.Logit.hessian` at `pipeline.py` import time.
`X.T @ diag(w) @ X` is a sum over rows, so it can be accumulated in chunks (default 500k rows at a
time) with peak memory bounded by one chunk instead of the full matrix — mathematically identical
result (chunked summation is exact here, not an approximation), same `.summary()`/`.conf_int()`/
everything downstream, just computed without the giant intermediate. Discussed with you and you
approved this over subsampling rows or switching away from statsmodels.
